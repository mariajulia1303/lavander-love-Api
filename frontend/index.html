Como funciona

  1. Você entra com e-mail e senha e a API devolve um token de sessão (vale 60 min).
  2. Com esse token você gera a sua chave de API: uma por pessoa, nível ESCRITA, plano BASICO.
  3. Clique em Usar esta chave no painel: ela vai no header X-API-Key de todas as requisições.
  4. Gerar de novo troca o valor da chave (a anterior para de funcionar na hora).

O banco é em memória: se a API for reiniciada, contas e chaves somem. Aí é só criar a conta de novo.

Testes dos recursos da Parte 2

Rate limit (429)

Dispara várias requisições seguidas em GET /categorias. O algoritmo é token bucket: cada requisição gasta uma ficha do balde, que recarrega aos poucos. Sem chave o balde é do IP (5 fichas, recarga de 15/min); com chave, do plano dela (GRATUITO: 8 fichas, 20/min). Balde vazio dá 429 com Retry-After. Quem insiste depois do 429 (5 negadas seguidas) leva uma penalidade de 30 s.


      


      

        
Política de limites

        
Consulta GET /limites (público): limites de cada plano, do acesso anônimo e global, a
          penalidade e quantas fichas você ainda tem agora.

        
        

      


      

        
Idempotência

        
Envia o mesmo POST /categorias duas vezes com a mesma X-Idempotency-Key
          e depois com o corpo diferente. Exige chave ESCRITA.

        
        

      


      

        
Versionamento

        
Busca o mesmo produto com X-API-Version: 1 e 2. Na v2 a resposta é mais enxuta
          (precoFormatado, disponivel, categoria resumida) e a listagem ganha filtros combináveis
          (troque a versão no topo e veja a busca da aba Produtos).

        
        
        

          

          

        

      


      

        
Chave de API e níveis

        
Tenta operações com chaves diferentes: sem chave (401), chave inválida (401), LEITURA tentando
          excluir (403) e LEITURA listando clientes (200).
